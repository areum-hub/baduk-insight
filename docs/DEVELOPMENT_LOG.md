## 왜 만들었나요?

좋아하는 바둑을 단순히 관전하는 데서 나아가, **프로기사의 실제 대국 기보를 한 수씩 복기하고 궁금한 착수를 AI에게 질문하며 스스로 공부**하기 위한 프로젝트입니다.

자체 바둑 대국 엔진을 만드는 대신, 기존의 KataGo 분석 엔진과 RAG 검색을 결합해 개인용 바둑 학습 도우미를 만드는 방향을 선택했습니다. 기보 출처는 **CWI 프로 바둑 아카이브**입니다.

## 한눈에 보는 개발 흐름

```text
Phase 1. 프로 기보 뷰어
  SGF 다운로드 / 업로드 → 수순 파싱 → 19×19 바둑판 재생
                        ↓
Phase 2. KataGo 착수 분석
  선택 수 직전 국면 → KataGo JSON 분석 → 승률·후보 수·변화도 표시
                        ↓
Phase 3. AI 바둑 공부 챗봇
  질문 → EmbeddingGemma 임베딩 → ChromaDB 관련 개념 검색
       → (실행한 경우) KataGo 결과와 결합 → Qwen 한국어 해설
                        ↓
Phase 4. 나만의 학습 기록 (예정)
  질문·북마크·반복 복습 기록 → 개인 학습 관리
```

## Phase 1 — SGF 프로 기보 뷰어

**문제:** 기보를 대량으로 AI 모델에 넣기보다, 선택한 대국을 **바둑판 위에서 직접 이해**하는 화면이 우선 필요했습니다.

**한 일 (코드 추가):**
- CWI 기보를 개인 PC로 내려받는 `scripts/download_cwi_samples.py` 작성
- `sgfmill`로 SGF의 메인 수순을 읽는 `src/sgf_service.py` 작성
- SVG 기반 바둑판 `src/board_svg.py`와 Streamlit 화면 `app.py` 작성
- 이전 수 / 다음 수 / 수순 슬라이더 지원

**왜 이렇게 했나요?** SGF는 착수 좌표와 수순이 있는 구조화 데이터이므로, 원본 기보 전체를 RAG 텍스트로 임베딩하지 않았습니다. 바둑판 재생과 문서 검색은 별도 기능으로 구성했습니다.

**남은 검증:** 실제 CWI 파일 3개 다운로드, 모든 수순의 포획·패스·표시 정확도, 브라우저 UI 실행.

## Phase 1 보완 — 자동 복기 플레이어 (2026-11-14)

사용자가 SGF 기보를 화면에 불러온 결과, **수순 0에서는 빈 바둑판만 표시**되고 Next 버튼으로 수동 진행해야 했습니다. 바둑을 학습할 때는 대국을 자동으로 감상하다가 궁금한 순간에 멈추고 질문하는 흐름이 필요하다고 판단했습니다.

**이번에 추가한 코드:**
- `▶ 재생 / ⏸ 일시정지` 및 이전·다음 수 버튼
- `1초 / 2초 / 3초` 수순 자동 재생 속도 선택
- Streamlit fragment로 바둑판 영역만 주기적으로 갱신
- 마지막 수에서 자동 정지, 수동 수순 탐색 시 재생 중지
- `src/playback.py`에 타이밍·이동 범위 계산을 분리하고 `tests/test_playback.py` 추가
- 자동 재생 중 오른쪽 KataGo 분석·챗봇 입력은 일시정지 후 이용하도록 설계

프래그먼트가 백그라운드 복귀 시 한꺼번에 여러 수를 뛰어넘지 않도록, 틱 한 번에 최대 한 수를 진행하는 방식을 선택했습니다.

**검증 상태:** GitHub에 구현 코드를 반영했습니다. 실제 사용자의 Streamlit에서 1·2·3초 재생, 일시정지, 재생 종료가 모두 정상 작동하는지는 아직 확인하지 않았습니다.

## 실제 실행 과정 업데이트 (2026-11-14)

- Ollama 초기 설치에서 `exit code 1` 및 명령 인식 오류가 있었으나, 이후 앱 설치 화면과 `ollama list`로 **EmbeddingGemma 2 270M / Qwen3 4B Instruct 모델 설치**를 확인했습니다.
- Streamlit 앱이 브라우저에서 실행되는 모습이 확인되었습니다.
- 로컬 SGF 파일이 없을 때 바둑판이 보이지 않는 문제가 있었습니다. 앱 내 다운로드 버튼과 `Upload SGF` 대안을 추가했습니다.
- 이후 사용자가 `F1.sgf` 파일을 불러와 **19×19 바둑판과 `0 / 284` 수순 카운터가 표시되는 화면**을 확인했습니다.
- 첫 화면이 빈 판인 이유는 수순 0이기 때문입니다. 다음 수/슬라이더로 이동하거나 자동 재생 기능으로 수순을 확인할 수 있습니다.
- 실제 KataGo와 RAG 연동 및 자동 재생 기능의 최종 통합 검증은 남아 있습니다.

## Phase 2 — KataGo 분석 연동

**문제:** 일반 LLM은 정확한 바둑판 형세 계산에 적합하지 않습니다. 실제 착수 평가에는 바둑 엔진이 필요합니다.

**한 일 (코드 추가):**
- `src/katago_client.py`에서 KataGo JSON 분석 요청/응답 처리
- SGF 수순 N을 선택하면 **N수 직전 국면**을 분석하는 기능
- 후보 수 3개, 변화도, 흑 기준 승률과 예상 집 차이 표시
- `configs/analysis_local.cfg` 및 모의 엔진 테스트 추가

**왜 이렇게 했나요?** KataGo는 바둑판 계산을 맡고, LLM은 사용자가 이해하기 쉬운 설명을 맡도록 역할을 분리했습니다.

**남은 검증:** KataGo 실행 파일 및 호환 신경망 모델 설치, 실제 국면 분석, 원본 기보의 규칙·덤과 분석 설정 일치 여부 확인.

**기능 제한:** 현재 분석은 수를 두기 **전** 후보 수를 보여줍니다. 실제 수가 얼마나 나빴는지 판단하려면 수를 둔 **후** 국면과 비교하는 기능이 추가되어야 합니다.

## Phase 3 — EmbeddingGemma + RAG 챗봇

**문제:** KataGo가 숫자와 추천 수를 제시하더라도 '축이 무엇인가?', '왜 연결이 중요한가?' 같은 바둑 개념을 공부할 자료가 필요합니다.

**한 일 (코드 추가):**
- `knowledge/`에 직접 작성한 기초 바둑 학습 노트 **10개** 추가
- `src/ollama_client.py`: Ollama를 통해 임베딩 및 한국어 답변 생성 요청
- `src/rag_pipeline.py`: ChromaDB 색인, 질문 임베딩, 관련 문서 최대 3개 검색
- Streamlit 화면에 **Build / refresh knowledge index** 버튼과 채팅 UI 추가
- 참고 문서 경로 표시 및 KataGo 분석을 실행한 국면에 한해 그 결과를 답변에 제공
- Ollama/벡터 DB 모의 객체 테스트 작성

**각 모델의 역할:**

| 구성 | 역할 |
| --- | --- |
| `embeddinggemma-2:270m` | 질문과 설명 문서를 벡터화하는 임베딩 모델 |
| ChromaDB | 유사한 바둑 개념 문서 검색 |
| `qwen3:4b-instruct` | 검색된 자료와 실제 엔진 분석을 근거로 한국어 설명 작성 |
| KataGo | 착수에 대한 수치·후보 수 분석 (선택적) |

**핵심 설계:** RAG는 **바둑 지식을 검색**하고, KataGo는 **바둑판을 계산**합니다. LLM이 계산하지 않은 승률을 지어내지 않도록 지시문에 제약을 추가했습니다.

**남은 검증:** 실제 Ollama 임베딩·챗 실행, ChromaDB 색인·검색, SGF와 KataGo를 포함한 화면 전체 통합 테스트. 초기 지식 노트는 초급 개념 10개로, 모든 프로기사의 수를 설명할 수 있는 수준은 아닙니다.

## 처음 실행하면서 확인한 문제

**2026-11-14 / Windows PowerShell**

- Python 패키지 설치 로그가 표시되어 의존성 설치를 진행했습니다.
- `ollama pull embeddinggemma-2:270m` 입력 시 **'ollama' 명령을 인식하지 못한다**는 오류가 발생했습니다.
- 이 오류는 현재 보이는 증상상 Python 코드가 아니라 **Ollama 미설치 또는 PATH 미설정** 문제입니다.
- [Windows 실행 가이드](SETUP_WINDOWS.md)에 설치 확인, PowerShell 재시작, 경로 점검 절차를 작성했습니다.
- **Ollama 설치 완료 및 RAG 챗봇 실동작은 아직 확인되지 않았습니다.**
