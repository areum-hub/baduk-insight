## 프로젝트의 목적

관심 있는 프로 바둑 기보를 한 수씩 복기하면서, 필요한 때에만 KataGo의 추천 수를 확인하고, 바둑 개념은 직접 작성한 한글 학습 노트로 빠르게 복습하는 것이 목표입니다. 기보 수집량을 늘리거나 AI가 프로기사의 의도를 추측하는 기능은 우선순위가 아닙니다.

## 현재 동작 기준으로 정리한 구현 흐름

```text
CWI 공식 SGF / 로컬 SGF 업로드
  → sgfmill 수순 재생 → 2초 고정 자동 복기 및 바둑판 SVG
                              ├─ KataGo 선택형 착수 전 분석
                              │    → 승률·집 차이·추천 수·대안
                              └─ 바둑 개념 학습
                                   → 16개 Markdown 학습 노트
                                   → 분야별 공개 설명 카드
```

과거의 `EmbeddingGemma → ChromaDB → Qwen` 생성형 RAG 흐름은 **학습·실험용 모듈로 저장소에 남아 있지만 현재 챗봇의 답변 경로에서는 사용하지 않습니다.** 느린 생성형 답변 메뉴는 제거했습니다.

## 개발 단계별 변경 이력

### 1. SGF 뷰어와 원본 기보 연결

- `src/sgf_service.py`: `sgfmill`로 기보 읽기, 메인 수순 재생, 대국 메타데이터 파싱
- `src/board_svg.py`: 9·13·19줄 바둑판과 돌의 SVG 표시
- `src/cwi_source.py`: CWI 공식 HTTPS `.sgf` URL만 허용해 직접 읽고 최대 2MB 및 SGF 유효성 확인
- CWI의 이세돌–알파고 1·4·5국 선택 및 다른 원본 SGF URL 직접 입력 기능
- `Upload SGF`에서 **CWI 원본**과 **내 PC 파일** 중 선택 가능
- `truststore`로 Windows 시스템 신뢰 인증서를 이용하는 HTTPS 연결 방식 추가

**직접 확인된 사실:** 사용자 PC의 Streamlit 화면에서 SGF를 로드한 후 19줄 바둑판과 `0 / 284` 수순 표시를 확인한 적이 있습니다. 다만 최신 CWI 원격 불러오기와 SSL 오류 해결 성공 여부는 확인하지 못했습니다.

### 2. 자동 복기

- `src/playback.py`의 수순 이동 로직과 Streamlit 주기 갱신
- **재생/일시정지**, **이전/다음**, **수순 슬라이더**
- **2초마다 한 수** 고정, 재생 속도 선택 UI 제거
- 마지막 수에서 자동 정지, 수동 이동 시 자동 재생 중단
- 0수에서 나타나던 불필요한 파란 착수 안내 삭제

구현 코드는 GitHub에 반영되었지만, Windows 브라우저의 재생 간격·정지 동작·백그라운드 탭 복귀까지 종합 검증되었다고 주장하지 않습니다.

### 3. KataGo 착수 분석

- `src/katago_client.py`: 별도 설치한 KataGo 분석 엔진에 JSON 요청 전달
- 선택한 **N수의 직전 국면(N-1수 이후)**을 계산
- 흑 기준 승률·예상 집 차이, AI 추천 수, 추가 후보·예상 수순 표시
- 바둑판의 **주황 테두리 = 실제 착수**, **파란 테두리 = AI 1순위 추천**
- 기본 **AI 탐색 횟수 5**, `b10c128` 경량 모델 경로 제안
- `src/local_settings.py`: KataGo 실행 파일/모델/분석 설정을 PC 전용 JSON으로 저장
- 대국 규칙과 백의 덤은 접힌 메뉴에서 확인. 기보에 규칙이 없으면 기본 규칙을 실제 규칙인 것처럼 표시하지 않음
- 같은 설정·국면의 KataGo 분석은 서버 메모리 캐시로 재사용하지만, 사용자 화면에는 캐시 안내 문구를 노출하지 않음

**현재 한계:** 분석마다 KataGo 프로세스를 새로 시작하므로 첫 실행은 느릴 수 있습니다. 추천 수와 실제 수가 다르다는 사실만으로 **승률 손실이나 착수 실수**라고 판단하지 않습니다. 실제 PC에서 선택한 경량 모델의 실행 성공 및 분석 속도를 계속 검증해야 합니다.

### 4. 바둑 학습 노트와 분야별 공개 학습 화면

- `knowledge/`: 처음의 바둑 기초 노트 10개에 **선수·후수, 패, 빅, 끝내기, 실리·세력, 공격·수비** 6개 추가 → **총 16개**
- `src/fast_study.py`: 질문에 포함된 바둑 용어로 관련 노트를 선택하고 일부 원문을 즉시 표시
- **바둑 개념 학습**은 분야를 선택한 뒤 원하는 제목 카드를 클릭하여 그 설명을 읽도록 변경
- `AI 자세히 설명` 선택 메뉴 및 Qwen 실시간 생성형 답변 경로 제거
- 챗봇 아래의 **참고한 학습 노트**/검색 근거 문서 펼침 박스 제거
- 사이드바 **03 · 학습 자료**는 노트 개수만 기본 표시, 색인 관리·동기화는 접힌 상세 메뉴에 보관
- 기존 질문 대화 이력 UI를 제거하고 학습 자료를 읽는 방식으로 단순화

**정확한 범위:** 공개 학습 카드는 작성된 노트의 원문 설명을 보여줍니다. 특정 판의 정확한 최선 수·승률을 계산하거나 사람이 생각한 내용을 추론하지 않습니다. 해당 노트가 없으면 근거가 부족하다고 알립니다. 실제 CPU/GPU 모델 추론 없이 동작하도록 설계되었으나 PC에서의 실측 응답 시간은 확인하지 못했습니다.

**2026-11-15 기존 검색 방식 개선 이력(현재 UI에서는 미사용):** 빠른 학습 질문에서 노트 제목·일부 고정 용어에만 의존하던 방식을 개선했습니다. 바둑 개념별 유사어, 노트 제목·본문의 관련성, 질문에 맞는 노트 발췌 문장을 함께 사용합니다. ‘돌을 이어 두다’, ‘초반 어디부터’, ‘패감은 언제’처럼 문장이 달라도 같은 개념을 찾는 테스트를 추가했습니다. 이 과정에서도 Ollama 호출은 없고 실전 수읽기 결과를 추측하지 않습니다.

**2026-11-15 무료 로컬 챗봇 추가:** 분야별 카드 학습은 유지하고 아래에 `Ollama + qwen3:1.7b` 기반 선택형 질문 기능을 추가했습니다. PC에서 실행되며 유료 API 비용은 없지만, 모델 다운로드·로딩과 CPU 처리 속도는 실제 PC에서 확인해야 합니다. 선택한 학습 카드와 관련 노트만 제공하고 KataGo 승률·최선 수는 추측하지 않도록 프롬프트를 제한했습니다.

### 5. 기존 RAG 학습 실험 코드 유지

`src/rag_pipeline.py`, `src/ollama_client.py`에는 EmbeddingGemma 임베딩·ChromaDB 검색·Qwen 모델을 통한 RAG 실험 코드가 남아 있습니다. 사이드바의 **AI 검색 자료 동기화** 버튼도 사용 가능합니다.

하지만 **현재 분야별 학습 카드는 이 색인을 사용하지 않습니다.** 따라서 사이드바의 `보유 학습 노트 16개`와 `검색 색인 문서 수`가 다르더라도 기본 빠른 답변은 가능합니다. 이전 RAG 실험의 색인 동기화를 실행하려면 Ollama와 임베딩 모델이 필요합니다.

**2026-11-15 레이아웃 개편:** 사이드바 기본 접힘, 상단 65% 바둑판·35% AI 분석으로 구성했습니다. 학습 카드와 무료 로컬 질문 챗봇은 두 영역 아래에서 **전체 너비**를 사용하도록 이동했습니다. 실제 Windows 브라우저의 반응형 배치는 확인이 필요합니다.

**2026-11-15 학습 UI 정리:** 메인 Baduk Insight 헤더·부제, 바둑 개념 학습 제목과 안내 문구 글꼴을 확대했습니다. 하단 로컬 챗봇 제목과 모델명 안내를 화면에서 삭제하고, 학습 내용 바로 아래에 질문 입력창이 이어지도록 배치했습니다. 챗봇 작동 기능은 유지합니다.

## 다음 검증 순서

1. Windows에서 `git pull --ff-only origin main` 후 앱 재실행
2. 기보 불러오기 → 자동 재생·일시정지 → 복기 중 좌표 표시 확인
3. 사이드바에서 보유 학습 노트 16개 확인, 분야 선택 후 축·장문 학습 카드 클릭
4. KataGo 경량 모델 분석 결과 확인
5. CWI 원격 기보 연결 및 오류 대응 확인
6. `.venv\Scripts\python.exe -m pytest -q` 실행
